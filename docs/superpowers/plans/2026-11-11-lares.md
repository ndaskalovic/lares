# Lares for Proxmox VE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Chrome MV3 extension that docks an AI copilot panel into the Proxmox VE web UI. The copilot acts via the Proxmox API with the user's own session, guarded by manual/auto confirmation modes, using the user's Anthropic or DeepSeek key.

**Architecture:**
- The service worker owns the key, storage, the guard and the agent loop, and calls the LLM through one Anthropic-format client.
- Content scripts own the Shadow-DOM panel, the same-origin Proxmox API executor and the API schema (index + describe).
- The two talk over one `runtime.connect` port.

**Tech Stack:**
- Plain JS with JSDoc and `// @ts-check`, checked by `tsc --noEmit`.
- `node --test` for pure modules.
- No runtime dependencies. Dev dependencies: `typescript`, `@types/chrome`.

**Spec:** `docs/superpowers/specs/2026-11-11-lares-design.md`

## Global Constraints

- Display name `Lares for Proxmox VE`, short name `Lares`. No Proxmox logo anywhere.
- `minimum_chrome_version: "116"`. Manifest V3. Background is `{"service_worker": "background/sw.js", "type": "module"}`.
- Permissions are exactly:
  - `storage`, `unlimitedStorage`, `scripting`, `activeTab`
  - host `https://api.anthropic.com/*`, `https://api.deepseek.com/*`
  - optional host `https://*/*`
- No runtime dependencies, no bundler, no `eval`/`new Function`, no remote code.
- The API key is never sent to a content script or the page. The content script never reads `chrome.storage`; call `setAccessLevel({accessLevel: 'TRUSTED_CONTEXTS'})` where it exists.
- LLM endpoint `POST {base}/v1/messages`, with:
  - bases `https://api.anthropic.com` and `https://api.deepseek.com/anthropic`
  - headers `content-type: application/json`, `authorization: Bearer <key>`, `anthropic-version: 2026-10-21`, `anthropic-dangerous-direct-browser-access: true`
  - never send `temperature`, `top_p`, `top_k`
- Models:
  - Anthropic: `claude-sonnet-5-5` (default), `claude-opus-5-5`, `claude-haiku-5-5`
  - DeepSeek: `deepseek-v4-pro` (default), `deepseek-flash`
  - plus a free-text custom model ID
- Thinking `{type: "adaptive"}`. Effort: `medium` (Anthropic), `high` (DeepSeek). `max_tokens: 32000`.
- Prompt caching:
  - Static system block gets `cache_control: {type: "ephemeral", ttl: "1h"}`.
  - Top-level `cache_control: {type: "ephemeral"}` for Anthropic only.
  - Tools, the static block, the per-chat memory block, provider, model and effort stay byte-stable within a chat.
  - History is append-only and never edited.
- Tool results are capped at 16000 chars (head + tail, marker `[truncated N chars, narrow the query]`).
- Proxmox:
  - same-origin `fetch('/api2/json' + path)`
  - bodies `application/x-www-form-urlencoded`
  - CSRF header `CSRFPreventionToken` on every non-GET
  - never call `/access/ticket`
- Task polling every 1500 ms, up to 60 s, returning `exitstatus` + the last 20 log lines. `OK` and `WARNINGS: n` count as success.
- Retries: 429/500/503/529 and stream `error` events retry up to 3 times, using `retry-after` seconds or else backoff of 1 s, 2 s, 4 s. Never retry 400/401/402/403/413.
- Panel heartbeat: the panel posts `{type:'ping'}` every 20 s while the port is open, so the service worker survives long confirmations.
- Light theme: `font: 13px helvetica, arial, verdana, sans-serif`, border `#cfcfcf`, accent `#3892d4`, header bg `#f5f5f5`. Dark theme: primary `hsl(205,100%,32%)`, text `hsl(0,0%,95%)`, bgs `hsl(0,0%,20%)`/`15%`/`10%`, border `hsl(0,0%,40%)`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Session expired or logged out mid-chat** (401 even after a CSRF refresh). The tool returns `ERROR: Proxmox session expired. Log in again.` with no retry loop. Test in Task 7.
2. **User clicks Stop or closes the panel while a tool_use is pending.** Every `tool_use` in history still gets a matching `tool_result` (`Stopped by user.`), so the next message doesn't 400. Test in Task 5.
3. **The model sends a malformed path**: `{node}` left unfilled, `..`, `?query`, `#`, an absolute URL, or a missing leading `/`. It is blocked before any fetch, with a clear reason. Test in Task 1.
4. **Huge tool output** (syslog, big configs, task logs). It is capped head+tail at 16000 chars, and the model is told to narrow the query. Test in Task 5.
5. **Hostile strings in API data or model output** (`<img onerror>`, `javascript:` links in VM notes). Rendered escaped; only `http(s)` links become anchors. Test in Task 8.

### Task 5: Agent loop

**Files:** Create `extension/background/agent.js` and `test/agent.test.js`.

**Interfaces:**
- Consumes:
  - `classify`, `decide` (Task 1)
  - `callModel`, `PROVIDERS` (Task 2)
  - `TOOLS`, `buildSystem`, `memoText` (Task 3)
  - store functions (Task 4)
- Produces:
  - `capResult(text: string, max = 16000) → string`
  - `class Session`
    - `constructor({post: (msg) => void, origin, index: string|null, env: {user, version}, deps?})`. `deps` overrides `callModel`/store for tests.
    - `async open(chatId?: string)`: loads or creates the chat. A new chat snapshots `memo` from current notes and fixes `provider`/`model` from settings. Posts `state`.
    - `async send(text: string, context: string|null)`: runs one agent turn.
    - `toolResult(id: string, content: string, isError: boolean)`: resolves a pending dispatch.
    - `stop()`
    - `async summarize()`
    - `async setMode(mode)`: also persists via `setSettings({mode})`
- Messages posted to the panel:
  - `{type:'state', chat:{id, messages}, chats, mode, model, ready: boolean, setupHint?: string}`. `ready` requires the key for the chat's provider plus consent.
  - `{type:'delta', text}`
  - `{type:'tool', id, name, input, decision}`
  - `{type:'done', usage, long: boolean}`. `long` is `input_tokens + cache_read_input_tokens + cache_creation_input_tokens > 150000`.
  - `{type:'error', message}`

**Loop behavior:**
1. Push a user message. Its content is `[{type:'text', text:'[Selected in UI: ' + context + ']'}]` (only when `context` is set), then `{type:'text', text}`.
2. Repeat at most 25 times:
   1. Call `callModel` with `system = buildSystem(index, chat.memo)` and `TOOLS`.
   2. Push `{role:'assistant', content}` verbatim and save.
   3. If `stop_reason !== 'tool_use'`, stop. On `refusal`, post an error `The model declined this request.`
   4. Otherwise, for each `tool_use` in order:
      - `remember`/`forget` run against the store. `remember` returns `Saved as ${id}. Applies from the next chat.`
      - `pve`: `classify` then `decide(mode)`. `block` resolves locally as `ERROR: Blocked: ${reason}` and still posts a `tool` message so the panel shows it. Otherwise post `tool` and await `toolResult`.
      - `pve_describe`: post with decision `run` and await.
      - If `stop_reason === 'max_tokens'` with a trailing `tool_use`, the result is `ERROR: Output was truncated; tool not executed.`
   5. Push one user message of `tool_result` blocks: `{type:'tool_result', tool_use_id, content: capResult(...)}`. Errors get `is_error: true`, and the content is prefixed with `ERROR: ` if it isn't already. Save, then continue.
3. Post `done`.

**Stop:** abort the fetch via `AbortController`. Every unresolved tool_use gets `Stopped by user.`, so history stays valid. Post `done`. On a thrown error, post `error` and keep history valid the same way.

**Summarize:** one `callModel` with the same system and tools, plus an extra user message `Summarize this conversation so it can be continued in a new chat: goals, findings, current state, open items. Be brief.` The appended messages are not saved to the old chat. Then create a new chat whose first user message is `Summary of the previous chat:\n` + the text, and post `state`.

### Task 7: Proxmox client (content)

**Files:** Create `extension/content/pve.js` and `test/pve.test.js`.

**Interfaces:**
- Produces (globals):
  - `readTicket(cookie: string) → {user: string, issued: number}|null`. Parses `PVEAuthCookie` (URL-decoded), shaped `PVE:<user>:<HEX>::sig`. It returns null when the cookie is missing or the ticket is a `PVE:!tfa!` partial; `issued` is in ms.
  - `parseCsrf(html: string) → string|null`. Regex `CSRFPreventionToken:\s*'([^']*)'`. The value `'null'` returns null.
  - `csrfAge(token: string, now = Date.now()) → number` (ms since the token's hex timestamp)
  - `selectionFromHash(hash: string) → string|null`. Splits on `:` and takes item 2. It must start with `=`; that item is URI-decoded and returned without the `=`. Otherwise null.
  - `class PveClient`
    - `constructor({fetchFn = fetch, doc = document, sleep})`
    - `async request(method, path, params = {}) → {ok: boolean, text: string}`
    - `async version() → string`

**request behavior:**
- Params encode via `URLSearchParams`: booleans as `1`/`0`, arrays as repeated keys.
- GET puts params in the query string. Other methods send a urlencoded body with the `CSRFPreventionToken` header.
- CSRF:
  - Read it from the DOM's inline scripts on first use.
  - Refresh it via `fetchFn('/')` + `parseCsrf` when it is null or older than 90 min.
  - On a 401, refresh once and retry once. A second 401 returns `{ok:false, text:'Proxmox session expired. Log in again.'}`.
- Response:
  - `ok` returns `JSON.stringify(json.data)`.
  - An error returns `${status} ${statusText}` plus `JSON.stringify(json.errors)` if present.
- UPID tasks: if the method is not GET and `data` is a string starting with `UPID:`:
  - Take the node from `upid.split(':')[1]`.
  - Poll `/nodes/${node}/tasks/${encodeURIComponent(upid)}/status` every 1500 ms for up to 60 s.
  - Then fetch `/log?start=0&limit=500` and keep the last 20 lines.
  - Return `{upid, status, exitstatus, log}` as JSON text. `ok` is false unless the exit status is `OK` or starts with `WARNINGS`.
  - On timeout, return `{upid, status:'running', note:'Still running; poll GET /nodes/{node}/tasks/{upid}/status'}`.
